# ハーネス設計ガイド — 「設計」を「実際に動く形」にするために

このドキュメントは、Harness Studio が扱う「agentic workflow / ハーネス」とは何か、
それが現実にどう実装されるのか、そしてエクスポートがどうやって「実際に使える形」を
生成しているのかを説明します。

関連: [AGENTIC_WORKFLOW_BASICS.md](AGENTIC_WORKFLOW_BASICS.md)(基礎・パターン集)/
[SELF_IMPROVEMENT_LOOP_GUIDE.md](SELF_IMPROVEMENT_LOOP_GUIDE.md)(自己改善ループ)

## 1. ハーネスとは何か

LLM エージェントの「ハーネス(harness)」とは、**モデルの外側にあって、エージェント
を安定して目的に向かわせるための足場一式**のことです。モデルは賢くても、裸のままでは
「何をどの順でやるか」「いつ止まるか」「結果が良いか悪いか」を管理できません。
それを担うのがハーネスです。

| ハーネスの部品     | 役割                               | Harness Studio での対応                |
| ------------------ | ---------------------------------- | -------------------------------------- |
| 共有コンテキスト   | 全ステップ共通の前提・規約・制約   | ワークフロー設定の「共有コンテキスト」 |
| ステッププロンプト | 1 ステップ分の指示と期待する出力   | ステップ(種類プリセット + 指示)        |
| ワークフロー制御   | ステップの実行順序                 | 縦のパイプライン(ブロックの並び)       |
| 成果物の受け渡し   | 前ステップの出力を次に渡す         | 自動(各ステップの出力を後続に注入)     |
| 品質ゲート         | 「続行してよいか」の機械的な判定   | 「チェック」ステップ(構造化 PASS/FAIL) |
| ループ制御         | 合格するまで反復し、上限で打ち切る | 繰り返しブロック                       |
| ランタイム         | 上記すべてを実際に動かす実行環境   | エクスポート(下記)                     |

ポイント: **設計データ(JSON)はハーネスの「仕様書」であって、本体ではありません。**
本体は「仕様どおりにエージェント呼び出し・成果物受け渡し・ゲート判定・ループを実行
する仕組み」です。Harness Studio はその本体ごと書き出します。

## 2. エクスポートの使い分け

### Codex Runner(メイン)

OpenAI **Codex SDK**(`@openai/codex-sdk`)で動くスタンドアロンのランナーです。
各ステップは Codex のエージェントスレッドとして実行され、対象ディレクトリの中で
**ファイルの読み書き・コマンド実行**ができます(サンドボックス内)。

```bash
npm install
codex login                  # または export CODEX_API_KEY=...
node run.mjs --dir /path/to/repo "実行したいタスク"
```

- ステップ出力 → `runs/<タイムスタンプ>/` に成果物として保存され、後続に注入
- 「チェック」→ `outputSchema` による構造化出力で `{pass, reasons, fixInstructions}` を取得
- ループ → 不合格理由と修正指示を次の試行のタスクに前置して再実行。上限到達で
  UNRESOLVED 記録 + 続行
- ループ外のチェックが不合格 → 実行停止
- `manifest.json` の `runner.sandboxMode`(既定 `workspace-write`)と `runner.model` で調整可能
- `AGENTS.md` を対象リポジトリにコピーすると Codex が自動で読み込みます

### Claude Code Pack(サブ)

Claude Code 利用者向け。中身をリポジトリに展開して `/harness-run <タスク>` で
ワークフロー全体を実行できます。ステップごとのスラッシュコマンドも生成されます。

### workflow.json

設計の機械可読データ。ホーム画面からインポートして編集を再開できます。チームでの
共有や、独自ランタイムへの組み込みの土台にも使えます。

## 3. 良いワークフローを作るコツ

- **指示は「人に頼むつもり」で書く**。何をするか、何ができたら完了かが伝わる文に。
- **作る(実行)と確かめる(チェック)をループで対にする**。これが品質の要です。
  チェックの判定基準は「テストが通る」のように機械的に判定できる文にします。
- **ループには必ず出口を**。チェックステップか終了条件のどちらか + 最大回数。
- **共有コンテキストには再利用できる事実だけ**を書く(規約・制約・前提)。
  タスク固有の内容は実行時のタスク文で渡します。
- 作成画面の警告(⚠)は上のコツを自動チェックしたものです。

## 4. 実行時の安全について

- Codex Runner はサンドボックス(既定: `workspace-write` = 対象ディレクトリ内のみ
  書き込み可)で動作します。
- 対象リポジトリは git 管理下で実行し、終わったら差分を確認してからコミットして
  ください。
